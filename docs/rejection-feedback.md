# 拒绝反馈说明

拒绝反馈应说明具体原因、当前已知事实或本群要求，以及申请者可采取的操作。程序保持现有审核分支和 T/F/I 结果，只改进反馈内容。

| 情况 | 必须说明的内容 | 申请者操作 |
| --- | --- | --- |
| UID 不存在或格式错误 | 明确是 UID 未查到或格式错误 | 检查 UID；只填写 B站昵称或 UID，不附加其他内容 |
| 昵称搜不到或无法唯一确认 | 明确是昵称未匹配或同名账号无法唯一确认 | 检查完整昵称，或改填正确 UID |
| B站等级不足 | 实际等级、本群要求的最低等级 | 达到要求后重新申请 |
| QQ 等级不足 | 实际等级、本群要求的最低等级 | 达到要求后重新申请 |
| 未关注目标主播 | 指定主播 UID，关注任意一位即可 | 关注后重试；确认已关注时核对所填账号 |
| 粉丝牌未达标 | 目标主播 UID、粉丝牌最低等级、满足任意一位即可 | 核对账号及粉丝牌，满足要求后重试 |
| 退群记录 | 当前群的退群记录；时间仅在配置允许时展示 | 联系管理员核实是否可重新加入 |
| B站账号已绑定其他 QQ | 说明账号绑定冲突，不展示对方 QQ | 核对自己的账号，联系管理员核实绑定 |
| 当前 QQ 更换了 B站账号 | 说明现有绑定 UID 与本次账号不一致 | 使用原绑定账号，或联系管理员核实解绑 |
| 限制名单 | 说明命中本群限制名单，保留管理员设置的原因 | 联系管理员复核 |
| 规则配置在 I 分支拒绝 | 说明暂无法核验的项目及本群采用的拒绝策略 | 稍后重试或联系管理员；不把接口异常说成账号不存在或未关注 |
| 规则配置在 T 分支拒绝 | 说明命中了本群的拒绝规则及已满足的条件 | 联系管理员复核，不虚构“条件不足” |

## 自定义文案与完整性

- `reject_reasons` 和阶段分支的 `reason` 作为管理员补充说明保留，程序同时保留实际条件、测得值和要求。
- 旧版默认的“疑似机器人”“疑似冒用”等笼统推断改用可确认的等级、绑定等事实。自定义说明由管理员负责维护。
- 账号输入失败必须包含“请不要填写B站昵称或UID以外的内容”，自定义阶段文案不能掩盖该提示。
- 拒绝参数不再被应用按 120 字直接切断；多个原因去重后完整发送，完整原因同步保存在审计记录中。
- 实际拒绝参数、管理员阶段通知及 `/检查bili` 的最终拒绝说明使用同一套反馈生成逻辑。
- 空白或缺失说明使用可操作的兜底提示：请联系管理员核实具体原因。

## 验证

`tests/test_core_rejection_feedback.py` 覆盖各类条件、旧文案兼容、自定义说明、长文本、T/I 拒绝策略与退群时间展示。

`tests/test_bili_identity_routing.py` 的加群处理烟测验证实际 QQ 动作参数（模拟动作）、真实临时 SQLite 审计与管理员通知均保留具体原因，不主动审批真实 QQ 申请。
