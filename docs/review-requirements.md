# 当前审核规则

本页对照当前代码说明行为。历史原始需求见[归档](history/review-requirements-original.md)，其中旧拒绝文案不再作为当前输出标准。

## T/F/I 与最终动作

- T（`true`）：该条件已有证据通过。
- F（`false`）：该条件已有证据不通过。
- I（`unknown`）：资料不足、配置缺失、隐私限制、接口异常或查询尚未确认。

I 是条件状态，`ignore` 是最终流转动作，两者不能混用。

| 模式 | 分组结果 |
| --- | --- |
| `all_pass` | 有 F 则 F；无 F 但有 I 则 I；全 T 才是 T |
| `any_pass` | 有 T 则 T；无 T 但有 I 则 I；全 F 才是 F |

每组的 `on_true`、`on_false`、`on_unknown` 决定 `approve`、`reject`、`ignore` 或 `next`；T 不必然批准，I 也不必然忽略。条件列表用于汇总与展示，实际接口资料会根据整个管道所需条件收集，不保证按列表逐项发起请求并短路。

## 八项条件

| 条件 | T | F | I 的常见情况 |
| --- | --- | --- | --- |
| `bili_account` | 确认 UID/唯一精确昵称及账号资料 | UID 无效或不存在、确定无昵称匹配、多个同名精确匹配、空输入 | 接口失败、搜索结果不完整且无精确匹配、资料缺失 |
| `bili_level` | 当前 B站等级达到最低要求 | 低于最低要求 | 无法确认账号或等级、未配置大于 0 的最低等级 |
| `qq_level` | 当前 QQ 等级达到最低要求 | 可读取且低于最低要求，含有效 0 级 | 接口和事件均无有效等级、明确隐藏且无可用回退、门槛未配置 |
| `follow` | 关注任一目标 UID | 完整且可确认地未关注任何目标 | 目标未配置、接口/分页或隐私限制导致无法确认 |
| `medal` | 任一目标粉丝牌达到最低等级 | 可确认没有达标的目标粉丝牌 | 目标未配置、列表不可读取或字段缺失 |
| `no_leave_record` | 当前群无该 QQ 的退群记录 | 当前群有退群记录 | 模拟命令未提供申请 QQ |
| `no_conflict` | 已确认 UID 未归属其他 QQ | UID 已归属其他 QQ | B站身份或绑定查询未确认、模拟未提供 QQ |
| `no_identity_change` | 已确认该 QQ 未更换现有绑定账号 | 本次 UID 与该 QQ 已持有的 UID 不一致 | 身份或绑定记录未确认、模拟未提供 QQ |

多个关注目标、多个粉丝牌目标均满足任意一位即可。等级门槛设为 0 并不等于从管道移除该条件；要关闭某项校验，应修改流程的 `conditions`。

绑定是程序登记关系，不是 B站账号所有权证明。管理员 `/解除绑定 <QQ号>` 后，重新申请且批准成功才会为新账号建立归属；这不会删除历史申请审计或退群记录。

## UID 与昵称输入

先从 QQ 加群问题格式提取答案，再按下表分流：

| 输入示例 | 路径 |
| --- | --- |
| `123456`、`１２３４５６` | UID 资料接口 `/x/web-interface/card` |
| `UID:123456`、`B站UID：１２３，４５６`、`UID: 123_456` | 清洗后的 UID 资料接口 |
| `UID:abc123`、`UID:0` | UID 格式错误，本地判定，不发起昵称搜索 |
| `昵称123`、`昵称_123`、`昵称 带空格` | 用户搜索接口 |
| 无 UID 标记的 `123,456` | 含符号的昵称，不自动提取数字 |

显式 UID 清洗包含全角兼容字符、不可见格式字符、标记后外层引号/括号和数字分隔符。UID 校验接受 1 至 20 位 ASCII 数字且数值大于 0。两种路径不互相回退。

搜索优先使用 WBI 签名；取不到签名密钥时才走未签名搜索路径。精确匹配忽略首尾空白及英文字母大小写，内部字符必须匹配。一个精确匹配加其他模糊结果可接受；多个精确匹配为 F。无精确匹配时，只有结果完整才能确定为 F，否则为 I。

真实申请依赖 B站条件时还需配置可用 Cookie；缺少 Cookie 为 I。识别账号成功不等于批准，仍由群审核流程决定。

## 仓库示例流程

[review_pipeline.yaml](../review_pipeline.yaml) 是占位示例，实际流程以部署引用的 YAML 为准：

1. A 组 `all_pass`：无退群记录、账号确认、B站等级、关注、QQ 等级；F 拒绝，全 T 批准，无 F 且有 I 进入 B。
2. B 组 `any_pass`：目标粉丝牌；T 批准，F/I 忽略，但缺牌与无法读取的原因分开记录。

`no_conflict` 和 `no_identity_change` 是可选条件，仓库示例没有自动启用。限制名单在成功解析到 UID 后、进入分组前判断；只有非空原因的有效配置项参与。它还依赖管道中存在 B站身份相关条件以触发账号查询。

`next` 未指定 `goto` 时进入下一组；T 分支到末尾可自动批准，F/I 分支到末尾无下一组则视为路由错误，记录为忽略。命中路由循环也按路由错误处理，不进行未经确认的批准。

## 管理员检查与实际审批

`/检查bili <群号> <UID或昵称>` 只模拟 B站侧审核，不写申请、绑定、退群记录，不发 QQ 审批或阶段通知。它没有申请 QQ，相关条件为 I，不能用输出代替完整实际审批结果。`/检查qq` 查看已经记录的历史。

实际同意/拒绝先写 SQLite pending，再调用 QQ。超时或断连的结果保持 pending，暂停新审批，由超级管理员核对实际结果后执行 `/确认审批`。这与已移除的“回复 y/n 审核新申请”无关。

所有拒绝的具体事实、阈值、修正提示和自定义补充规则见[拒绝反馈](rejection-feedback.md)。
