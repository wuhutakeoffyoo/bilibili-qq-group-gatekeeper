# V3 功能状态与验收边界

此表描述仓库能力与可核验边界。当前集成、CI、生产切换和受控真实动作的结果需由对应运行记录说明；没有记录的能力不宣称已在生产验证。

本次部署使用 SnowLuma；[2026-10-26 生产记录](production-acceptance-20261026.md)保留接入和数据基线。[2026-10-30 核查](snowluma-request-incident-20261030.md)确认并修复原版申请转换缺陷，真实遗漏申请已补审为忽略。重启免登录与通过 SnowLuma 同意/拒绝真实新申请仍未验收。

| 能力 | 实现与限制 |
| --- | --- |
| 独立默认运行 | FastAPI 单一生命周期 + OneBot 正反向 WS；默认无 NoneBot 导入 |
| QQ 接入与补审 | SnowLuma/NapCat 独立契约、启动/重连及健康期间周期补扫、旧数字键与收件箱变体去重；QQ 登录由外部客户端管理 |
| SQL 配置统一 | v4、旧来源一次迁移、原始来源备份、版本 CAS、脱敏导出、追加式恢复 |
| 规则引擎 | 安全 AST、原始数值比较、Kleene T/F/I、v2 数组兼容与 goto |
| UID/昵称 | 严格单路、UID 清洗、QQ 误填拦截、唯一精确昵称及清晰反馈 |
| B站请求控制 | 全 HTTP 平滑限流、确定资料 TTL、在途合并、WBI、完整性检查 |
| 凭证 | 手动/CookieCloud/管理员扫码、原生刷新协议、配对状态持久化、generation/CAS |
| pending | 先持久化后调用、相关 QQ/UID/request 预约、精确证据适配和一次重试预算、人工确认 |

| 管理 | SQL 群策略、审计、绑定、退群、pending、凭证健康和运行状态 |
| 运维 | 本地日志、磁盘和 SMTP；不自动清理/云端归档 |

## 必须单独验证的外部能力

1. OneBot echo、重连与命令往返正常，不代表真实审批已生效；受控申请需核对回执、审计、绑定和用户反馈。
2. SnowLuma/NapCat 请求核验器按各自契约，严格匹配原机器人/flag/QQ/群及 `checked=false` 后才提供“仍未处理”证据，允许一次有界重发；旧 NapCat 数字 flag 不会自动通过 SnowLuma 重放。已处理标记不代表批准/拒绝成功；未知实现、缺字段或未知状态仍需人工，不能凭成员存在自动确认。
3. B站扫码、刷新、指纹、动态评论与 UP 视角属于会变化的社区协议；fixture 能证明协议编排，真实账号可用性需只读/受控验收。
4. 对群员执行提醒、删除评论、自动关注、刷新确认或移除成员是外部写操作，不包含在普通只读烟测中。
5. 所有权证据只能说明验证时持有对应账号/消息能力，不保证账号永不转让、无人代操作或 QQ 永不受风控。
6. 当前粉丝牌检查不能代替有效舰长、大航海等级或到期时间。未实现的 guard 条件不能写入规则示例。

## 仍不提供的旧功能

- 云端日志归档及上传后删除。
- 推送新申请后回复 `y/n` 的人工审核；`/确认审批` 仅恢复未知动作。
- 任意 Python/CEL 代码执行、未知表达式名称。
- 多 Uvicorn worker 或多活审核实例的集群部署。
- 仅靠默认占位模板即可获得真实审核策略。

历史阶段的核心抽离、YAML 编辑器和全局暂停说明已由 V3 替代；原文保留于[历史规划](history/development-roadmap-20260621.md)与旧 ADR，不应继续用于安装指导。
